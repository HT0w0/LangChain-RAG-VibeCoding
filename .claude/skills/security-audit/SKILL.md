# security-audit：安全审计

## 零、先把威胁模型写在报告最前面

**不写这一段，后面的等级全是错的。**

| 事实 | 决定了什么 |
|---|---|
| 有**网络入口**：FastAPI 服务 + 浏览器前端，多用户 | 存在「越权」这个角色 —— 用户 A 能碰到用户 B 的数据，这是要重点查的 |
| 有**两种身份**：`admin` 与普通用户，知识库管理是 admin 独占 | 「漏挂一个 `require_admin`」是真实且致命的 |
| 持有**真实付费凭据**：百炼 API key（`.env`） | 泄露不只是「难看」，是**有人拿你的额度花钱** |
| **是公开仓库**（求职作品集） | 任何提交过的字节都算已公开；而且**作品集的要求更高** —— 审计报告会被看 |
| 目前只跑在本机、演示量级 | 但代码是按「可部署」写的，**按可部署的标准查**，别按「反正只有我」放水 |

**为什么必须先写：** 不写就会套用两种错误的尺子。一种是单机应用的尺子（「没有远程攻击者，什么都不算事」），另一种是互联网大厂的尺子（「没上 WAF、没做 DDoS 防护 = 高危」）。两种都会把真正要紧的「越权读别人会话」「密钥进了 git 历史」淹掉。

## 一、四档严重度 —— 判据必须能核对，不是感觉

| 档 | 判据 |
|---|---|
| **严重** | **现在就能触发**，后果是这三样之一：拿到/改掉别人的会话或知识库、拿到有效凭据、**不该公开的东西被公开**（公开仓库里发出去就收不回） |
| **高** | 后果同上，但**需要用户做一个不寻常的动作**才能触发（把服务开到公网、把 `.env` 发给别人） |
| **中** | **不需要改动代码就能触发**，但需要某个目前不成立的条件（比如「如果有人把 CORS 改成 `*`」） |
| **低** | **必须先改代码**（新增界面、新增路由）才可能触发；或纯属最佳实践，去掉不改变任何现实风险 |

**中 / 低 的分界只有一句话：想要触发它，是不是得先动代码？**
要动 → **低**。不要动、只是缺个时机 → **中**。

> 这条分界是用来的替代那个含混的说法（「条件已经齐了，只差一个入口」）——「差一个入口算不算齐」两种读法都通，于是不同的人会对同一处代码给出不同的档。换成「要不要先动代码」之后就不再有歧义。

**每一条都必须能写出「谁、怎么触发、造成什么后果」。写不出来 → 它就不是漏洞，删掉，不要凑数。**

判断「现在能不能触发」，靠的是第零节那些事实，不是想象力。

## 二、四条最容易翻车的地方（都是实测出来的）

### 1. 看着像漏洞、其实不是 —— 定性前先核对来源

| 看起来像 | 实际是什么 | 怎么核对 |
|---|---|---|
| `password: str = Form(...)` | 表单**字段名**，不是硬编码口令 | 看右边是类型标注还是字面量 |
| ``select(User).where(User.id == uid)`` | SQLAlchemy 的**参数绑定**，不是拼 SQL | 找有没有 `text(f"...{...}")` 或 `+` 拼串 |
| `allow_origins=["http://localhost:5173"]` | **白名单**，而且是收紧的（不是 `*`） | 看有没有通配符 |
| `react-markdown` 直接渲染模型输出 | **默认不渲染原始 HTML**，XSS 面很窄 | 看有没有加 `rehype-raw`；本项目 `AnswerText.tsx` 里有一条注释明确说**不要放开** |
| `JWT_SECRET` 有默认值 | 默认值本身是**刻意的**（本机开发友善），而且有校验器会告警 | 看有没有 `field_validator` 提示；再看它会不会在 `production` 下被真正拦住 |

**先跑脚本，再动脑：** `node .claude/skills/security-audit/scan-secrets.mjs .`
它把机械部分钉死了（密钥样式扫工作区＋扫历史、本地引用与远端逐个对照）。**别自己凭印象说「我 grep 过了」。**

### 2. 不许编前提 —— 引用项目自己的说法之前，先把原文读出来

**规矩：凡是引用 README / 注释 / 文档 / 提交信息来支撑结论的，必须先把那段原文读出来贴进报告。读不到 → 删掉这条结论。**

⚠️ **按大意核对，不要背行号。** 文档会被人精简、改写，照着旧行号去核，会核出一个根本不在文件里的句子。每次引用之前重新读一遍**当前**的文件。

这条在**这个**项目里不是假设：2026-10-09 迁移这套装置时按它查了一遍，就查到 `README.md:46` 写着中间件做「用户级限流」，而 `RATE_LIMIT_QPM` / `RateLimitedError` 在全仓**没有任何一处使用** —— 配置项和异常类都在，线没接。

**「文档承诺了、代码没做」是本项目最该被抓出来的一类问题**，因为它同时骗过读文档的人和读代码的人。

### 3. 公开仓库：工作区、本地、远端是三件事

- **工作区干净 ≠ 历史干净** —— 密钥提交过又删掉，仍然躺在历史里
- **本地有什么 ≠ 远端有什么** —— 本机可能有一条永远不该推的分支

跑一次 `scan-secrets.mjs` 的第 2、3 节就有答案。**报告里必须写清楚「我扫的是哪个范围」。**

> 本项目的特殊之处：`.env` 已经被 `.gitignore` 挡住，所以**工作区扫描一定扫不到它** ——
> 但那说明不了任何事。真正要确认的是**它有没有在历史里出现过**，以及 `data/` 下
> 那几份真实的开发库有没有被提交过。这两个问题第 2 节才答得了。

### 4. 认证与授权：本项目的重灾区，且**天然是静默的**

漏挂一个 `require_admin`、少写一个 `WHERE user_id = ?`，**页面照常打开、接口照常返回 200**。没有任何报错，没有任何日志。所以这一栏**必须枚举，不能抽查**：

- `app/api/routers/admin.py` 与 `kb.py` 里的**每一个**路由 → 逐个确认挂了 `require_admin`
- 会话/消息/文档的**每一个**读取与删除路径 → 逐个确认查询条件里带了归属校验
- 报个数：**枚举了几个路由 / 几个查询点**。报不出个数就等于没枚举

## 三、检查清单

按这五栏过。**每栏都要在报告里出现结论，哪怕是「未发现」。**

**① 敏感信息泄露** —— `.env` 有没有进过历史；硬编码的密钥/口令；真实 API key；`data/` 下的开发库与上传文件；本机绝对路径（尤其 `D:\Claude Code\...` 这种带用户目录的，出现在作品集文档里会暴露本机结构）；日志里有没有打过 JWT

**② 注入类** —— SQL（看值是**绑定**还是拼接；本项目的查询走 SQLAlchemy，重点找 `text()` 和字符串拼接）；**路径穿越**（上传文件名 —— 本项目 `store_upload` 用 uuid 生成存储名，去核对它有没有被绕过）；**XSS**（markdown 渲染有没有放开原始 HTML；antd 有没有地方用了 `dangerouslySetInnerHTML`）；**提示注入**（检索到的资料里写着「忽略以上指令」时，系统提示有没有把它当数据）

**③ 认证与授权** —— 见上面第 4 条，必须枚举；`JWT_SECRET` 默认值会不会在真实部署里被用上；token 有效期；密码哈希是不是 argon2id（不是 md5/sha1）；**JWT 里有没有塞 role**（塞了的话撤权不会立即生效，`core/security.py` 的模块文档解释了为什么不放）

**④ Web 服务特有** —— CORS 白名单（**绝不能是 `*`**，尤其 `allow_credentials=True` 时）；上传的类型/大小白名单；**限流有没有真的接上**；错误响应会不会把内部细节（堆栈、SQL、文件路径）回显给前端；`/docs` 在生产要不要关；SSE 端点有没有上限（一个客户端能不能挂着几千条连接）

**⑤ 公开仓库特有** —— 见上面第 3 条。另外：**作品集仓库里的文档本身就是被审查的对象** —— README 里的架构图、`docs/` 下的实测记录，有没有写出不该公开的东西（内部地址、真实凭据、别人的名字）

## 四、报告形状

```
# 安全审计报告

**审计对象**：<哪个目录> / <哪个分支，远端还是本地>
**结论**：一句话 —— 有没有严重/高危，要不要立刻做什么
**威胁模型**：这个软件面向什么场景（决定下面怎么分档）

## 严重 / ## 高 / ## 中 / ## 低
  - **<问题>** — `<文件:行>`
      现象：代码/配置是什么样
      谁能利用、怎么触发：
      后果：
      怎么修：

## 正面确认
  （查过且做对的地方 —— 免得下次重复劳动，也让用户知道哪些已被验证）

## 建议顺序
```

每一档没有内容就写「无」，不要省略 —— 「严重：无」本身就是结论。

## 五、只报告，不改代码

看见问题**不要顺手修**。安全改动会碰认证、权限、CORS、上传路径，改动本身就有风险，**必须由用户拍板**（CLAUDE.md §二）。

报告里可以给修法，但**不动手**。用户说改才改。

用户说了「存档」。你要做三件事，**一步都不能跳**。

## 第 1 步：派 `gitcommit-agent`

用 Agent 工具，`subagent_type: gitcommit-agent`。

它会并行跑单元测试和质量评审、发通行证、检查有没有过期的证需要补发，
最后交回一份**「提交准备单」**。

> ⚠️ **新建的 agent 文件要重启会话才认得。** 如果这一步报
> 「Agent type 'gitcommit-agent' not found」，就是碰上了这件事 ——
> **别改用别的 agent 顶替**，直接告诉用户：关掉重开 Claude Code 再敲一次 `/gitcommit`。
> （这是实测过的：`.claude/commands/` 里新建的文件当场就认，`.claude/agents/` 里的不认。）

**它不会提交** —— 这是刻意的（子 agent 没法向你提问，见该 agent 的说明）。
提交这一步由你在主对话里做，因为只有你能停下来问用户。

## 第 2 步：把准备单**原样**摆给用户，然后停下

把 agent 交回来的准备单**照着摆出来**（该列的文件、该贴的报错、该有的条目都要在），
**不要改写成你自己的话、不要替它总结**。用户要看到的是原始结论。

然后在末尾加上这一句话，**一字不改**：

> 你点头后，`git-save` 会**提交**；配了远端的话还会**推送上去**（也就是这些内容会公开）。
> 确认要这样吗？

**然后停下等用户回答。** 不要用「我先提交了」「应该没问题」之类的说法绕过这一步。

## 第 3 步：用户点头了才存档

用户明确说可以了（「好」「提交」「可以」这类），才调用 **`git-save` 技能**。

**git-save 一个字都不要改**，也不要绕过它自己敲 git 命令 ——
它是这个项目里唯一负责存档的地方。闸门在它**下面**拦（git 的 pre-commit 钩子），
git-save 自己不知道有闸门这回事，这是刻意设计的。

## 用户说不的时候

别提交。问他想改什么，改完**重新走第 1 步**（代码变了，通行证就作废了）。

## 出岔子的时候

- **准备单里写着某位检查员没过**：照原样摆给用户看，把报错贴出来。
  **不要自己修完再提交** —— 那是另一件事，先让用户知道。
- **闸门把提交拦下了**：说明通行证和当前代码对不上（多半是发完证之后又改了东西）。
  重新走第 1 步，**不要用 `git commit --no-verify` 绕过去**。
- **用户就是要跳过检查**：告诉他那是他自己在终端里敲 `git commit --no-verify` 的事，
  **你不代劳**。

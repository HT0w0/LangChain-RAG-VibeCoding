# 提交闸门

一句话：**没有通行证，Claude 提交不了。**

> 这一套是从《记账APP》那个项目迁移过来的（2026-10-09），并按本项目的技术栈重做了
> 发证命令、注释统计口径、安全威胁模型。**迁移了什么、为了什么改，见文末「与源项目的差异」。**

## 怎么用

在 Claude Code 里说一句 **`/gitcommit`**（或者说「存档」）。就这一句。

## 谁负责哪一段

```
用户： /gitcommit
  │
  ├─ 主对话 → 派 gitcommit-agent
  │              ├─ 并行派 tester + quality-engineer
  │              ├─ 两人各自发通行证
  │              ├─ 检查谁过期了、补发
  │              └─ 交回一份「提交准备单」
  │
  ├─ 主对话 → 把准备单原样摆给用户 → 【停下等回答】
  │
  └─ 用户点头 → 调 git-save（提交；配了远端才推送）
                     │
                     ▼ 没有有效通行证 → git 直接拒绝
```

**为什么确认那一步留在主对话、不交给 agent**：**子 agent 没有向用户提问的工具**
（源项目实测验过：子 agent 拿到的工具里没有 `AskUserQuestion`）。而规矩是
「先看到提交信息、确认了才提交」—— 所以那一步只能在主对话做。

手动挡（一般用不着）：

```bash
node .claude/gate/stamp.mjs --kind unit                                    # 发单验证（自己跑四条命令）
node .claude/gate/stamp.mjs --kind quality --findings <一个JSON文件路径>    # 发质量证
node .claude/gate/stale.mjs                                                # 哪张证过期了
node .claude/gate/gate.mjs                                                 # 手动跑一遍闸门看结果
node .claude/gate/check-detect.mjs                                         # 自检：命令识别（29 项）
node .claude/skills/comments-check/count-comments.mjs --selftest           # 自检：注释口径（12 项）
```

## 两道闸门分别拦谁

| | 拦谁 | 怎么分辨 |
|---|---|---|
| **闸门 B**（Claude 侧） | **只拦 Claude** | Claude Code 原生钩子，本来就只有 Claude 走得到 |
| **闸门 A**（git 侧） | **只拦 Claude** | 看环境里有没有 Claude 的标记 |
| **用户自己在终端敲** | **不拦，放行** | —— |

**分辨依据**：Claude Code 会在它启动的每个子进程环境里留下 `CLAUDECODE*` 标记，
用户自己开的终端里没有。

**为什么一次认三个名字**（`CLAUDECODE` / `CLAUDE_CODE_ENTRYPOINT` /
`CLAUDE_CODE_SESSION_ID`）而不是只看一个：这些是 Claude Code 的内部约定，
将来改了名，只看一个就会**静默地不再拦 Claude** —— 钩子照跑、一声不吭。
多认几个，改掉一个也不至于全线穿帮。

⚠️ **判断方向别改反：没有标记 → 放行。** 反过来的话，一旦改名，
用户自己的终端会被重新拦上，同样一声不吭。

## 文件

| 文件 | 干什么 |
|---|---|
| `../agents/gitcommit-agent.md` | **编排者**。派两位检查员、补发过期证、交回准备单。**它不提交** |
| `../commands/gitcommit.md` | **触发器**。派上面的 agent，把准备单摆给用户，点头了才调 git-save |
| `lib.mjs` | **两处闸门共用的判据**（指纹怎么算、证怎么读、怎么判过期）。只此一份 |
| `gate.mjs` | 闸门 A 的本体。git 的 pre-commit 会调它 |
| `stamp.mjs` | 发证。自己 `git add -A` 冻改动、自己跑四条命令 |
| `stale.mjs` | 打印哪张证过期了（给编排者用） |
| `check-detect.mjs` | 自检：「这条命令是不是 git commit」认得对不对（29 项） |
| `../githooks/pre-commit` | 闸门 A 的入口（**必须 LF 行尾**） |
| `../hooks/detect.mjs` | 命令识别（拆出来是为了能单独测） |
| `../hooks/pretooluse-commit.mjs` | 闸门 B（Claude 侧） |
| `pass-unit.json` / `pass-quality.json` | 通行证本身。**运行期产物，已写进 `.gitignore`** |
| `findings-quality.json` | 质量评审员写的输入。同上，已忽略 |

一次性配置（本机 `.git/config`，不随仓库走）：

```bash
git config core.hooksPath .claude/githooks
```

## 顺序（这是命门）

```
两位检查员并行跑 → 各自发证（发证时脚本自己 git add -A）
   → 编排者检查哪张过期了、补发
   → 给用户看提交信息 → 用户点头 → git-save 提交
```

**发证脚本自己做冻结**，是刻意的：顺序一旦搞反，证上记的指纹就是旧的，
提交被拒，而报错只会说「指纹对不上」—— 完全指不到真正的原因。

**并行带来的竞态**：tester 会新建测试文件，quality-engineer 可能在那些文件出现
**之前**就发完了证 —— 所以编排者在两人都回来之后要跑一次 `stale.mjs` 补发。

### ⚠️ 通行证必须留在 `.gitignore` 里（本项目特有的一条）

指纹算的是**索引树**（`git write-tree`），而 `git-save` 提交前会再跑一次 `git add -A`。
如果通行证本身是被跟踪的，**它一被改写就会改变这棵树** → 指纹对不上 →
**闸门把每一次提交都拦下**，而报错只会说「指纹对不上」。

源项目把整个 `.claude/` 都忽略了，所以碰不到这个坑。本项目要把它提交进作品集，
就必须在 `.gitignore` 里显式排除运行期产物。**这一条删不得。**

## 实测记录（2026-10-09，全部实跑过）

| 验的什么 | 结果 |
|---|---|
| 无通行证 → 闸门 B 拦 | ✅ 命令**根本没跑**（中文说清缺哪两张） |
| 无通行证 → 闸门 A 拦 | ✅ 退出码 1 |
| **去掉 Claude 标记 → 放行** | ✅ 退出码 0。**同一个脚本、同一个缺失状态，唯一差别是那个标记** —— 这才说明钩子真的在看它 |
| 两张证有效 → 放行 | ✅ 退出码 0 |
| 单验证真的自己跑命令 | ✅ pytest 615 条 + `ruff check` + vitest 62 条 + `tsc -b`，四条都过才发证 |
| **改了文件但没 `git add`** | ✅ 证**仍然新鲜** —— 指纹算的是索引树，不是工作区 |
| **改了文件并 `git add`** | ✅ 证**立即作废**（这就是命门） |
| 命令识别自检 | ✅ 29/29 |
| 注释口径自检 | ✅ 12/12 |
| 新建 `settings.json` 后要不要重启 | ✅ **不用**，当场生效（首次敲 `git commit` 就被拦） |
| `githooks/pre-commit` 行尾 | ✅ 纯 LF（`.gitattributes` 的 `eol=lf` 也兜着） |
| 发证脚本挑对了解释器 | ✅ 走 `.venv/Scripts/python.exe`，不是系统 `python` |
| 仓库路径带空格时能不能起 python | ✅ 能（绝对路径 + 不走 shell） |

> **倒数第二行和「改一行代码就作废」这两条，合起来才是准确的**：
> 证绑的是**即将提交的内容**。没 `git add` 的改动不会进提交，所以也不该让证作废 ——
> 这个行为是对的，不是漏洞。

## 迁移时改了什么（与源项目的差异）

| 部件 | 改了什么 | 为什么 |
|---|---|---|
| `stamp.mjs` | 单验证从「`npm test` + `npm run typecheck`」换成**四条命令**：`pytest` · `ruff check` · `vitest` · `tsc -b` | 本项目是 Python + TS 双栈，两条命令盖不住 |
| `stamp.mjs` | 挑 `.venv` 里的 python，找不到就**明说** | 系统 `python` 可能没装 pytest / ruff，而症状会是「闸门说测试没过」—— 指不到原因 |
| `stamp.mjs` | 给 python 加 `-X utf8` | Windows 下 python 往管道写中文按 GBK 编码，不解码成 UTF-8 的话，**错误信息自己就是乱码** |
| `stamp.mjs` | 噪音过滤多滤一条 jsdom 的 `Not implemented:` | 它恰好排在输出最后，不滤的话「62 条全过」看起来像「报了三行错」 |
| `count-comments.mjs` | 支持 Python，**docstring 计入注释** | 实测只数 `#` 是 12.7%，算上 docstring 是 33.6%。本项目「为什么」几乎全写在 docstring 里，只数 `#` 会**对最认真的目录报假警报** |
| `count-comments.mjs` | 新增 12 项自检 | 它出错的后果是静默的 —— 迁移当天就撞到一次（捕获组读错一位，整个目录报成 100%） |
| `count-comments.mjs` | 分档阈值改成实测值向下取整（30/15/25） | 源项目的 40/20/30 是给另一个代码库定的，照搬会让闸门一上来就全红 |
| `scan-secrets.mjs` | 加百炼 key 样式 | 通用 `sk-` 样式**过不了点号**，而百炼 key 中间有点 —— 正好漏掉本项目唯一的真凭据 |
| `scan-secrets.mjs` | 加占位符过滤（6 条噪音 → 2 条） | 一道总在响的警报等于没有警报 |
| `scan-secrets.mjs` | 新增第 4 节：`data/` 有没有进过仓库 | 本项目 `data/` 下是真实开发库与上传文件。**数据库文件没有肉眼可见的密钥样式**，只能直接问 git |
| `security-audit` | 威胁模型整个重写 | 源项目是**离线单机**（没有远程攻击者、没有第二个用户）；本项目有网络、多用户、admin 权限、付费凭据。照搬会把「越权读别人会话」这类真问题淹掉 |
| 新建 `CLAUDE.md` | §五 编码约定 16 条 | `quality-engineer` 第三维的**权威**。源项目那份是 73KB / 34 条，攒了两周；这份只写**在代码里查实过的**，以后撞到真 bug 再加 |
| `.gitignore` | 排除 `pass-*.json` / `findings-quality.json` | 见上文那条 ⚠️。源项目整个 `.claude/` 都忽略，所以没这个问题 |

## 已知代价与局限

1. **这是习惯装置，不是安全边界。** `git commit --no-verify` 永远能绕过（git 自带）。
   能做的只是**不让 Claude 用**，并让你自己在需要时能用。
2. **质量那一半是模型的自我报告。** 单测那一半是真的机器判定（发证脚本自己跑四条命令），
   质量那一半没有任何机器能验证 —— **别把两者当成同等可信**。
3. **闸门 B 挡不住「把 git commit 写进脚本再执行」**（它只认命令文字）——
   但闸门 A 照样兜得住，因为脚本是 Claude 跑的，环境里带着标记。
   ⚠️ 这层现在**是有条件的**：它靠 Claude 的标记认人。三个标记名将来全改了，
   这条旁路就没人管了。改名的信号是「闸门 A 突然不拦了」，而**它不会自己喊**。
4. **`--no-verify` 那句提示没实测过**（源项目里想验的时候被权限系统拦下了）。
   「紧急时能用它跳过」目前只是 git 的文档行为。
5. **`ruff format` 不跑**，是刻意的（见 `pyproject.toml` 与 `CLAUDE.md` §5.12）。
   看到 `ruff format --check` 报一堆文件，那是预期内的。
6. **本仓库还没配远端。** `scan-secrets.mjs` 第 3 节因此给不出答案。
   推之前必须再跑一次。

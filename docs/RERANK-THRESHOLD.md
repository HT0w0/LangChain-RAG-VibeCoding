# 重排阈值:机制一直都在,缺的只是一个数字

> 数据来源:`backend/scripts/rerank_probe.py`,实测于 2026-10-09,
> `qwen3.7-text-rerank`,`top_n=5`。
> **本文的数字与模型版本绑定**——换重排模型必须重跑探针,分数的绝对尺度
> 随模型而变,旧阈值不作数。
>
> 两次独立运行的分数统计逐位相同(min 0.7837 / median 0.9952 / max 1.0000),
> 所以这台机器上这组数是可复现的,不是某一次的网络抖动。

## 这一层在做什么

重排之后会按分数砍一刀,低于阈值的候选直接不进上下文
(机制在 [`retrieval._apply_rerank`](../backend/app/services/retrieval.py))。
而 `RERANK_SCORE_THRESHOLD` 的默认值是 **0.0**——等于不过滤。

这不是「还没配好」,是一个刻意的欠账:阈值必须**测出来**才能给,拍一个数字
比不给更糟,因为它看起来像有依据。代价是那一刀从来没落下过,
「不相关的资料别进上下文」这件事当前完全靠提示词约束模型,
没有结构性的第二道防线。一个语料里答不了的问题会照常走完一次完整的
LLM 调用,拿到一句「资料中没有找到相关内容」——答案是对的,但本可以更早短路。

## 为什么不能靠感觉给一个数

因为重排分数是**查询相关**的,而且不同问题的分数尺度会交错。配置注释里
记着一手观测:

```
KB 里有 RX9070 显卡和 27 寸显示器两行
问「RX9070 显卡多少钱」  → 相关行 0.9924 | 无关行 0.0637
问「这款显卡的保修期是几年」(语料里没有)
                          → 0.1527 | 0.0764
```

注意第二行:**一个完全跑题的问题,在相关段落上拿到了 0.1527,比第一行里
无关段落的 0.0637 还高。** 所以「把阈值卡在 0.1」既能滤掉跑题问题,
也会顺手砍掉正常问题里的第二候选——两个目标是交错的,不是单调的。
4 个样本定不了这件事,只能扫。

## 测量方法

- **语料 22 段**:6 个商品 × 3 类版块(价格库存 / 规格参数 / 保修售后)
  + 4 份通用政策(发货、退货、运费、发票)。刻意做出「同一个问题在六个
  商品上都能问」的样子,否则重排只要认出商品名就能拿高分,扫出来的阈值虚高。
- **问题 28 条**:22 条可答(每条**只标注一条**含答案的段落)+ 6 条跑题
  (语料里一条都答不了,它的正确答案是拒答)。
- **28 次重排调用**(每条问题一次,一次带上全部 22 段),而不是 616 次
  (每对一次)——重排接口本来就是「一个查询 + 一串文档」的形状。
- 每条问题都对**全部 22 段**打分,再由脚本离线模拟不同阈值下的后果。

判据是三类计数,不是一个「安全/不安全」的结论:

| 计数 | 含义 | 它坏了会怎样 |
|---|---|---|
| 相关段落保留率 | 含答案的段落有多少活过阈值 | 掉下去 = 系统答不出它本该答得出的问题 |
| 无关段落残留数 | 不含答案的段落有多少被带进上下文 | 涨上去 = 模型有材料可编 |
| 跑题拒答率 | 语料答不了的问题里,有多少被清干净 | 掉下去 = 该说「不知道」的时候硬答 |

## 实测结果

### 分数分布

```
含答案的段落  n=22   min=0.7837  median=0.9952  max=1.0000
其余段落      n=594  min=0.0005  median=0.0710  max=0.7822
```

两者的**中位数**差了 0.92,分开得很好。问题全在尾部:最差的含答案段落
是 0.7837,最好的无关段落是 0.7822——**相差 0.0015,统计上就是并列。**

### 排名

22 条含答案段落**全部排在第 1 名**,一条都没有掉到 `top_n=5` 之外。
也就是说在这个语料上,截断这一步不误伤,阈值是唯一起作用的筛子。
(这不是重排有多神,而是语料太干净:每个问题只有一条段落含答案,
其余 21 段连擦边都算不上。真实语料不会这么听话。)

### 阈值扫描(已复刻生产的 `top_n=5` 截断)

| 阈值 | 相关段落保留 | 可答率 | 跑题拒答率 | 残留无关段落 |
|---|---|---|---|---|
| 0.00 | 22/22 | 100% | 0% | 118 |
| 0.10 | 22/22 | 100% | 0% | 112 |
| 0.15 | 22/22 | 100% | 17% | 102 |
| 0.20 | 22/22 | 100% | 17% | 92 |
| 0.25 | 22/22 | 100% | 33% | 76 |
| 0.30 | 22/22 | 100% | 33% | 57 |
| 0.40 | 22/22 | 100% | 67% | 26 |
| **0.50** | 22/22 | **100%** | **100%** | 12 |
| 0.60 | 22/22 | 100% | 100% | 2 |
| 0.70 | 22/22 | 100% | 100% | 1 |
| 0.80 | 20/22 | 91% | 100% | 0 |

「跑题拒答率 100%」出现在 **0.50**:这是第一个能让六个跑题问题一条资料
都捞不到的阈值。再往上,可答率一直到 0.70 都还是满的。

于是 **`[0.50, 0.70]` 是一段两个目标同时成立的区间**:在这个区间里,
该答的问题都还答得出来,该拒的问题全都被拒了。区间内部唯一的差别是
残留的无关段落从 12 条降到 1 条。

## 这个测量最脆弱的地方

**决定 0.80 那个「零污染点」的,只有一对标注——而这一对很可能是标错了的。**

分最高的无关段落是这一条:

```
0.7822  rx9070.price  ←  「下单后多久发货」
```

`rx9070.price` 的原文里写着「库存 12 件,**下单后当天出库**」。而通用政策
`policy.shipping` 写的才是标准答案(24 小时内出库、偏远地区加 3-5 天)。
按「只有标注段落才算相关」的严格口径,前者是无关;可它确实含有一句
部分正确的答案。

把这一对改判成相关,下界立刻从 0.7822 掉到 **0.6656**(下一条是
`k870.warranty` 配「K870 用的是什么轴」——那条才是不折不扣的无关)。

所以「零污染需要 0.80」这个结论,一半是数据、一半是标注口径。
而 0.80 恰好要付出 2/22 的召回——**这两件事是同一件事:上界(最差的
相关段落 0.7837)和下界(最好的无关段落 0.7822)只差 0.0015,
一条边界标注就能让它们互换位置。**

这不影响 `[0.50, 0.70]` 这个区间的可靠性——那一段离两边的边界都还远。
它影响的是「再往上调能不能免费换来更干净的上下文」:不能,上面没有免费的了。

## 这个测量证明不了什么

- **证明不了真实用户的问法都在这个区间里。** 28 条问题是我按电商客服
  的口吻写的,比真实提问整齐得多:没有错别字、没有一句话里问三件事、
  没有指代不明的追问。真实语料里最差的相关段落多半会低于 0.7837,
  也就是上界会往下走。
- **证明不了语料规模下的行为。** 22 段候选,而线上一个知识库跑几千段。
  候选越多,「某一条不相关的恰好分很高」的概率越大——`max(无关)` 会
  单调上升,而它正是下界的定义。**所以线上需要的阈值只会比这里更高,
  不会更低。** 这条是这个测量里唯一一个方向明确的推断。
- **证明不了多候选相关的情况。** 每个问题只标注一条段落。真实语料里
  保修问题可能同时命中商品售后卡和通用政策,那时保留一条就够,
  算出来的召回率会偏高。

## 当前取值与它的代价

配置里取 **0.50**,理由是:

1. 它是**第一个**让跑题拒答率达到 100% 的阈值。再往下探没有意义——
   0.40 能保住的东西 0.50 一样保得住,却多放进 14 条无关段落。
2. 它离上界(0.7837)还有 **0.28** 的余量。取 0.70 的话余量只剩 0.08,
   而上面已经说了,真实问法必然比这批手写问题更乱——余量买的是
   「真实语料变差时不会突然开始丢答案」。
3. 代价是**每条可答问题平均多带 0.55 条无关段落**(12 条 / 22 问)。
   这个代价由提示词兜底:资料是数据不是指令,答不了就明说。
   而反过来(阈值取高、丢掉本该答得出的资料)没有任何兜底——
   用户只会看到一句「资料中没有找到相关内容」,看不出这是配置造成的。

## 重跑方式

```bash
python backend/scripts/rerank_probe.py
python backend/scripts/rerank_probe.py --thresholds 0.0 0.05 0.10 0.2 0.5
```

**联网、花钱、依赖模型版本。** 脚本自己进不了单元测试(它联网),
但它内部那段**扫描数学是纯函数,已被 `backend/tests/test_rerank_probe.py`
离线钉住**——阈值边界是闭区间、分母取标注总数而不是幸存者数、
`top_n` 决定候选集大小。那几条要是错了,上面的表会整体平移一格,
而表本身看不出异常。
